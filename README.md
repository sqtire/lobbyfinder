# osu! MP Pool Scanner (multi-tenant)

Watches **every** osu! multiplayer lobby and logs the ones that play a tournament's beatmap pool. Anyone can sign in with osu! (OAuth, `identify` scope), create a tournament, set its pool (up to 30 difficulty IDs), invite staff, sync a mainsheet roster, remove lobbies, and export. Results are public per tournament at `/t/<slug>`; editing is limited to members. Runs as two always-on Railway services sharing one Redis.

- **worker** — one process, one ≤1 req/sec limiter, three fronts in priority order:
  1. **rolling sweep** — walks every match once it is ~4h old (closed by then), writes it to the **match index** (`mpf:idx:<day>`: match id → maps played, ~1 MB/day, `INDEX_RETENTION_DAYS`), and stores full lobby detail *once* when any enabled tournament's pool intersects, linking a reference per tournament (tombstones honored). Runs regardless of how many tournaments exist — the index is the product.
  2. **tenant backfill** — a tournament's "rescan": scan the index for its pool over a match-id range (no API), link lobbies already stored (no API), read only lobbies nobody has stored yet (1 request each). Queued FIFO, one active per tournament. Ranges the scanner never read are reported as id gaps the owner can rescan.
  3. **owner walk** ("Admin rescan" in the UI) — the raw re-read of a match-id range into the index (1 request per osu! match). Site-owner only (`OWNER_OSU_IDS`); used to seed history / fill gaps after downtime. Output is shared by every tournament.
  Background fronts get a batch sized by the sweep's health, so the sweep never falls behind because of them.
- **web** — Next.js: landing (`/`), tournament pages (`/t/<slug>`), owner panel (`/owner`), APIs under `/api/t/<slug>/*` and `/api/owner/*`.
- **Redis** — tenants, members, sessions, the match index, the global hit store + per-tenant references/tombstones/rosters, queues, telemetry.

## Deploying the multi-tenant version over the old single-tenant one

1. In osu! account settings → OAuth → your existing application, set **Application Callback URL** to `https://<web-domain>/api/auth/callback`.
2. Railway env — web: add `OSU_CLIENT_ID`, `OSU_CLIENT_SECRET`, `OWNER_OSU_IDS`, `PUBLIC_BASE_URL` (`APP_PASSWORD` is no longer used). Worker: nothing new required.
3. Push. The worker resumes its cursor and starts indexing; the old `mpf:config` pool no longer drives matching by itself.
4. Sign in on `/`, open `/owner`, and **Adopt into tournament** — folds the legacy pool, lobbies, tombstones and roster into a tenant (copies only, idempotent). Within ~15 s the worker picks the tenant up and live matching continues under `/t/<slug>`. Then run one **Backfill** on that tournament for the current day to catch anything read between the deploy and the adoption.

## Roster sync formats

The mainsheet parser never assumes a layout. Per tab it tries, in order: (1) osu! profile links on player cells (rich links, `HYPERLINK()` formulas, raw URLs) — real user ids; (2) name + `#rank` cells; (3) a plain name grid — one team per row (`Team1: | name | name…`) or one team per column (team names in a header row, names below). Modes 2–3 match players by username against scanned lobbies. Mappool tables, schedules and single-column signup lists are rejected as grids; when the row/column orientation is ambiguous the preview offers a one-click flip. Whatever it finds is a preview the operator edits before committing.

## Stats tab + exports

Every tournament page has a **Stats** tab computed from its logged lobbies, pool and roster (server-side, `lib/stats.ts`), replicating the Stats v5 qualifier sheet: per map a team's score is the sum of its members' best scores (optionally capped to N scores), placements are `RANK` (ties share, unplayed = last), and the ranking method is selectable — Z-Sum (Σ Φ(z), sample stdev), average placements, max %, % difference or Zipfian — with ties broken by average score. Also: per-map team and player leaderboards, performance (match cost `2/(n+2)·Σ score/field-average`, MVPs, played %, averages, highest score) and mappool stats. Members can save the method/settings as the tournament default and export the whole thing as an `.xlsx` workbook (Summary, Team/Player placements, Team/Player leaderboards, Performance, Mappool, Grid) or the Teams-grid viewport as `.csv`. Validated against the 5USC26 qualifier sheet: 71/71 team placement rows, 380/380 player rows and match costs match exactly (with the sheet's mod-scaling quirk switched on).

## Final placements (1v1 brackets from a referee sheet)

`/placements` is a separate, one-click generator for round-robin / Swiss-style 1v1 events run from a referee sheet (built for AEROLS, lazer rooms). It reads **only the schedule** from the sheet — the mappool is always manual input — and produces the standard stats workbook plus a **Final Placements** sheet.

**Inputs.** (1) The referee sheet — either its Google Sheets link (must be "anyone with the link can view"; the spreadsheet is downloaded as .xlsx through the same export endpoint roster sync uses, no API key) or the file itself (File → Download → Microsoft Excel, uploaded on the page). Either way the tab (default `Chrono Schedule`, matched case-insensitively) is read with its cached formula values, so `FILTER()`-built tabs work; Google's CSV query endpoint is deliberately not used because it guesses and merges header rows. The tab needs a header row containing `stage`, `team red`, `team blue`, the two score columns between them (`-1`/`FF` = forfeit, blank = unplayed), `mp link` (+ `mp link 2…` for split lobbies; lazer `multiplayer/rooms/<id>` and legacy `community/matches/<id>` both work) and `first to` (or `best of`). Player cells that link to an osu! profile give exact user ids; plain names are matched by username, then by lobby activity. (2) The pool, one slot per line: `NM1 <upper id or link> <lower id>` — the first id is the upper (Tier 1) difficulty, any later id a lower tier of the same slot (lazer freestyle; `NM1 T2 <id>` on its own line also works), optional `[Round 3]` sections give a round its own pool, and a label starting with `TB` is the tiebreaker. "Read sheet" previews the stages (played / forfeited / unplayed, first-to) without touching the osu! API; stages are then ticked on or off.

**Counting rules.** A lobby game counts when it is a completed pool map on which *both* scheduled players posted a score. Games are taken in lobby order and capped at the sheet's `red + blue` score, so warmups, aborted maps and "for fun" maps after the match never count; a `TB` map only counts as the deciding game at (first-to − 1) each. Forfeit matches contribute the pool maps that were actually played (switchable); failed scores count (switchable); any playlist item can be dropped by id from the Games tab (e.g. a warmup that happens to be a pool map). Players are matched sheet-name → osu! username, falling back to lobby activity (the other scorer in a 1v1); renames are merged and noted. Points always come from the sheet; where the lobby reconstruction disagrees, the run notes it instead of overriding.

**Ranking.** Points (1 per win, forfeit wins included) → tiebreak → plain average → name; points always win. The tiebreak is selectable, and every variant is an *average over the slots a player played* with `k` (default 2) phantom "average" slots, so map count is neutral — a 4–0 sweep or a forfeit win neither helps nor hurts, and a 3-slot sample can't beat a 20-slot one on luck. A "slot" pools both tiers of a map, and the AEROLS rule applies inside this step only: scores set on the lower difficulty are multiplied by 0.95 (adjustable) before ranking; every visible stat stays raw.
- **Φ(z) average** (default): `z = (adjusted score − slot mean) / slot sample stdev` per counted play, `Φ(z)` averaged — measures consistency; one pop-off score barely moves it (a #1 and a #5 on a map differ by ~0.1).
- **z average**: raw z averaged — no saturation, top scores count proportionally.
- **Zipf placement average**: on each slot every player's best adjusted score is ranked and is worth `1/placement` (#1 = 1, #2 = 0.5, #3 = 0.33, #10 = 0.1) — top scores dominate. The phantom slots are worth the field's mean value.
Slots need ≥ 3 counted plays and a non-zero spread to count. Buchholz, raw map W–L–T, top-score counts and average placements are shown but never sorted on. If a "lower" id has a higher star rating than the slot's first id, the run notes it so a swapped line can't pass silently.

**Workbook.** Laid out like the Stats v5 / TNST results tabs: Final Placements (points → tiebreak, per-round results), Performance Scores (tiebreak alone, maps played, top scores, avg placement), Mappool Stats (one row per *difficulty*: best player/score/acc/mods/match, average, median), Individual Leaderboards (side-by-side blocks per slot, both tiers in one block, raw scores, T1/T2 column), Solo Placements (placement + best raw score per slot), Tiebreak Detail (the adjusted scores, adjusted placements and per-slot values the ranking actually used), Matches, Games, Summary.

**Running.** Starting a run is site-owner only (it spends osu! API requests — one or two `rooms/{id}/events` calls per lobby, paced by `PLACEMENTS_OSU_INTERVAL_MS`, default 1500 ms, on the web service's own `OSU_CLIENT_ID/SECRET`); results and the `.xlsx` export are public and every run is kept (last 30) under `<prefix>:plc:*` in Redis with lobbies cached for 60 days, so re-running with different settings is instant. One run at a time, with stall detection; progress is polled by the page. Workbook tabs: Final Placements (with per-round results), Performance Scores, Mappool Stats, Leaderboards, Scores Grid, Matches (sheet vs lobby reconciliation), Games (every lobby game with counted/excluded reason and item id), Summary.

**Local test.** `cd web && ../worker/node_modules/.bin/tsx --tsconfig tsconfig.json scripts/placements-smoke.ts [schedule.csv]` runs the engine + workbook offline on synthetic lobbies (`DEBUG_MATCH=<id>` prints one match). `scripts/placements-mock-api.ts <schedule.csv|table.json> 3222 [sheet.xlsx]` is a stand-in for Sheets (serves the .xlsx at the export URL) + osu! API; point `next start` at it with `PLACEMENTS_SHEETS_BASE=http://127.0.0.1:3222 PLACEMENTS_OSU_OAUTH_URL=http://127.0.0.1:3222/oauth/token PLACEMENTS_OSU_API_BASE=http://127.0.0.1:3222/api/v2` (test-only overrides) for a full end-to-end run.

## Local smoke test (worker)

`REDIS_URL=redis://127.0.0.1:6379/1 OSU_CLIENT_ID=x OSU_CLIENT_SECRET=y npm run smoke` in `worker/` exercises the index, coverage, prune, hit store, tenant links and the backfill state machine against a local Redis (no osu! calls except the deliberately-failing fetch path).
